# kata M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** kata のソースを `kata build` で APK にし、エミュレータ上でカウンター、見た目指定、入力欄とスクロールの3つのサンプルが仕様どおりに動く状態にする。

**Architecture:** Java 17 製のコンパイラ（字句解析 → 構文解析 → 検査 → ASM によるバイトコード生成 → SDK の build-tools による APK 組み立て）と、Java 製のランタイム2つ（Android 非依存の `runtime-core`、View に変換する `runtime-android`）。APK の組み立て経路を最初に手書きの Java クラスで端末まで通し、その後にコンパイラを載せる。

**Tech Stack:** Java 17、Gradle 8.10.2（wrapper）、ASM 9.7.1、JUnit 5.11、Android SDK（platforms/android-35、build-tools/35.0.0）、Python 3 と adb（端末での確認）。

**Spec:** `docs/spec/`（`index.html` から全章）。SSOT。各タスクは、該当する章を読んでから着手する。

## Global Constraints

- 仕様が正。挙動を新しく決めた場合は、同じコミットで `docs/spec/` を更新する。
- コンパイラの依存は ASM だけ。ランタイムは `android.jar` 以外に依存しない（AndroidX、Kotlin を入れない）。
- 生成するクラスファイルと両ランタイムは Java 8（版 52）向け。コンパイラ本体は Java 17。
- SDK は `ANDROID_HOME`、`platforms/android-35`、`build-tools/35.0.0`、`minSdkVersion` 26、`targetSdkVersion` 35。
- `kata` の標準出力は 07 の JSON 1つだけ。診断の `message` は英語。行と列は1始まり、列はコードポイント単位、終わりは範囲に含まない。
- 診断コードの意味と番号は 07 の一覧どおり。一覧にないコードを作らない。
- 検査を通ったプログラムがコード生成で失敗したら `E0999`。
- 外部ツールは引数の配列で起動する（シェルの文字列連結をしない）。
- Java のパッケージ：コンパイラは `dev.kata.compiler.*`、ランタイムは `kata.rt`。
- コミットメッセージの末尾に `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` を付ける。push はしない。

## Review Focus

1. **ASCII 以外と改行コード**：文字列リテラルやコメントに日本語や絵文字（サロゲートペア）がある、改行が CRLF、先頭に BOM がある。列がコードポイント単位でずれず、端末にも正しく表示されること。→ Task 6
2. **閉じていないソース**：`class A {` で終わるファイル、空のファイル、`.kata` が1つもない `src/`。構文解析の立て直しが無限ループせず、診断を返して終わること。→ Task 7、Task 5
3. **空白を含むパス、別の作業ディレクトリ**：プロジェクトのパスに空白がある、`kata` を別のディレクトリから呼ぶ。ビルドが通り、`artifact` と `file` がプロジェクトからの相対パスであること。→ Task 4、Task 5
4. **再描画で構造が縮む・種類が変わる**：`Column` の子が減る（フォーカス中の入力欄が消える）、ルートの部品の種類が変わる、入力欄の `onChange` の中で `value` を別の文字列に書き換える。落ちたり `onChange` が再帰したりしないこと。→ Task 16、Task 17
5. **境界の整数**：`9223372036854775807` と `9223372036854775808`、あふれる加算、負の数の `/` と `%`、`List<Int>` と `List<Bool>` の出し入れ（包む・取り出す）。→ Task 6、Task 11、Task 12

**Files:**

**Interfaces:**
- Produces:
  - `record AppInfo(String id, String name)`（`build` パッケージ）
  - `final class Sdk`：`static Sdk locate(Map<String,String> env) throws ToolFailure`（`E0901`、`E0902`）、`Path androidJar()`、`Path buildTool(String name)`、`Path d8Jar()`
  - `final class ToolFailure extends Exception`：`String code()`、メッセージ
  - `final class ApkBuilder`：`static Path build(Path project, Map<String, byte[]> classes, AppInfo app, Path kataHome, Sdk sdk) throws ToolFailure`。戻り値は `project/build/app.apk`。`classes` のキーは内部名（`app/counter/Counter`）。

手順（02 `#build-pipeline`）：
1. `build/classes/` に `.class` を書き出す。
2. `build/AndroidManifest.xml` を書く（02 `#manifest` のとおり。`id` と `name` は XML エスケープする）。
3. `aapt2 link -o build/base.apk --manifest build/AndroidManifest.xml -I <android.jar> --min-sdk-version 26 --target-sdk-version 35 --version-code 1 --version-name 1.0`
4. `java -cp <build-tools>/lib/d8.jar com.android.tools.r8.D8 --min-api 26 --lib <android.jar> --output build/dex <全 .class> <kataHome>/runtime/kata-rt-core.jar <kataHome>/runtime/kata-rt-android.jar`
5. `build/dex/classes.dex` を `base.apk` に追加する（zip ファイルシステム）。
6. `zipalign -f 4 build/base.apk build/aligned.apk`
7. `~/.android/debug.keystore` がなければ `keytool -genkeypair -keystore … -storepass android -keypass android -alias androiddebugkey -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Android Debug,O=Android,C=US"`
8. `apksigner sign --ks … --ks-pass pass:android --key-pass pass:android --out build/app.apk build/aligned.apk`

外部ツールが0以外で終わったら `ToolFailure("E0903", "<ツール名>: <出力>")`。

- `Button` と `TextField` のリスナーは、`update` のたびに新しい部品の `Action`/`Handler` を指すようにする。
- kata のコードが投げた例外は捕まえない（パニックとしてアプリを止める）。
