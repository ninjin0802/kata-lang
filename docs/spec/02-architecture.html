02 全体構成とビルド

リポジトリ構成

docs/spec/           この仕様書（SSOT）
compiler/            コンパイラと kata コマンド
runtime-core/        ランタイムのうち Android に依存しない部分
runtime-android/     ランタイムのうち Android に依存する部分
examples/counter/    M1 のサンプルアプリ（カウンター）
examples/styled/     M1 のサンプルアプリ（見た目の指定）
examples/form/       M1 のサンプルアプリ（入力欄とスクロール）
scripts/             エミュレータでの確認スクリプト

部品と依存

部品言語役割依存
compilerJava 17字句解析、構文解析、検査、バイトコード生成、APK の組み立て、kata コマンドASM
runtime-coreJava（Java 8 のクラスファイル）UI の値を表すクラス、KList、Action、Screenなし
runtime-androidJava（Java 8 のクラスファイル）KataActivity と、UI の値を View に変換する Rendererruntime-core、android.jar
  • コンパイラとランタイム自体のビルドとテストには Gradle wrapper を使う。
  • runtime-android は AndroidX を使わない。android.jar にあるクラスだけを参照する。
  • ランタイムを2つに分けるのは、生成したコードを Android なしのデスクトップ JVM でテストできるようにするため。

境界の決めごと

  • コンパイラの段階は、字句解析 → 構文解析 → 検査 → コード生成の順に一方向に進む。各段階は前の段階の出力だけを入力にする。
  • 検査を通ったプログラムは、コード生成で失敗しない（原則 P7）。コード生成で失敗した場合はコンパイラの不具合であり、E0999 を返す。
  • 生成したコードが参照するランタイムのクラスは、06 コード生成に列挙したものに限る。
  • 検査までの段階は JVM に依存しない。JVM に依存する処理はコード生成に閉じ込める。

kata プロジェクトの構成

<プロジェクト>/
  src/                 ソースのルート
    app/counter.kata   モジュール app.counter
  build/               生成物（kata build が作る）
    classes/           .class
    app.apk            完成した APK
  • 設定ファイルは持たない。アプリの ID と名前は app 宣言に書く。
  • モジュール名とファイルの位置は一致させる。module app.counter; は src/app/counter.kata に置く。

kata build の流れ

  1. 検査：src/ 以下の全 .kata を読み、診断が1件でもあればここで止まる。
  2. コード生成：build/classes/ に .class を書き出す。app 宣言から kata.gen.MainActivity も生成する。
  3. マニフェスト生成：app 宣言の id と name から build/AndroidManifest.xml を作る。
  4. DEX 変換：d8 で、生成した .class と2つのランタイムの jar を classes.dex にまとめる。
  5. パッケージ：aapt2 link でマニフェストを処理した APK を作り、classes.dex を追加する。
  6. 整列と署名：zipalign の後、apksigner で debug 鍵による署名を行い、build/app.apk を出力する。

アプリのビルドに Gradle と Android Gradle Plugin は使わない。Android SDK の build-tools を直接呼ぶ。

生成するマニフェスト

  • package は app 宣言の id。
  • application の android:label は app 宣言の name。テーマは @android:style/Theme.Material.Light。
  • Activity は kata.gen.MainActivity の1つだけ。android:exported="true" とし、MAIN / LAUNCHER の intent-filter を持つ。
  • Activity には android:configChanges="orientation|screenSize|screenLayout|smallestScreenSize|keyboardHidden|uiMode|density" を付ける。画面の回転などで Activity が作り直されず、画面の状態が保たれるようにするため。
