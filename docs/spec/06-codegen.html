06 コード生成

検査を通った kata プログラムを JVM のクラスファイル（Java 8、版 52）に変換する規則。

型の対応

Intlong
Boolboolean
Stringjava.lang.String
Unitvoid
Actionkata.rt.Action
Handler<T>kata.rt.Handler（型引数は消去する）
List<T>kata.rt.KList（型引数は消去する）。要素の Int は java.lang.Long、Bool は java.lang.Boolean に包んで持つ。
kata.ui の名前（Ui、Screen、Column など）kata.rt の同名のクラスまたはインターフェース

クラス

  • kata のクラスは public final の JVM クラスになる。親は java.lang.Object。
  • implements したインターフェースは、対応する JVM のインターフェースとして実装する。
  • フィールドは public。let は final を付ける。外部からの書き込みは検査で防いでいるので、JVM 側では制限しない。
  • コンストラクタは public で1つ。初期化の式を持たないフィールドを、宣言順に引数として受け取る。本体では、全フィールドを宣言順に初期化する。
  • メソッドは public final のインスタンスメソッド。引数は宣言順。
  • メソッド名は kata の名前をそのまま使う。ただし wait、notify、notifyAll、finalize は、java.lang.Object のメソッドと衝突しないよう、JVM 上では名前の後ろに $kata を付ける。kata のコードからは元の名前で呼ぶ。
  • 各クラスに SourceFile を、各メソッドに行番号の表を出力する。スタックトレースに kata のファイル名と行番号が出るようにするため。

式と文

forリストを1回評価してローカル変数に置き、添字を 0 から size の手前まで進めながら get で要素を取り出す。

app 宣言

app 宣言から、次のクラスを生成する。

package kata.gen;

public final class MainActivity extends kata.rt.KataActivity {
    @Override
    protected kata.rt.Screen createRoot() {
        return /* root の式 */;
    }
}

id と name はマニフェストに使う（02 全体構成とビルド）。

kata.ui の宣言にある、上記以外のすべてのクラス（kata.rt.TextField、Scroll、Color、Padding、Center など）core宣言と同じ名前、同じ順番のフィールドと、それを順に受け取るコンストラクタ。型は型の対応に従う。
kata.rt.KataActivityandroidandroid.app.Activity を継承した抽象クラス。protected abstract Screen createRoot()
  • kata.rt.Renderer（android）は UI の値を View に変換する。KataActivity の内部で使い、生成コードからは参照しない。見た目の値の範囲の検査と、変わった部分だけの反映もここで行う。
  • 前回の UI と新しい UI を比べて「何を更新するか」を決める処理は、Android に依存しない形で runtime-core に置き、デスクトップの JVM でテストする。Renderer はその結果を View に適用する。
  • KataActivity は 描画の流れを実装する。
