kata 仕様書08 テスト

08 テスト

仕様に書いた規則は、対応するテストを持つ。実装はテストを先に書いて進める。

テストの種類

種類確かめること実行環境
診断の照合テストkata のソースに対して、期待どおりの診断 JSON が返ること。デスクトップの JVM
実行テスト生成したクラスを読み込んで実行し、期待どおりの結果になること。デスクトップの JVM（runtime-core を使う）
ランタイムの単体テストruntime-core のクラスの振る舞い。前回と新しい UI を比べて更新内容を決める処理を含む。デスクトップの JVM
端末での確認APK を入れて起動し、画面が操作に応じて変わること。エミュレータ

診断の照合テスト

compiler/src/test/resources/cases/
  E0401-int-as-string/
    src/app/main.kata     入力
    expected.json         期待する出力（07 の出力の形）
  ok-counter/
    src/app/counter.kata
    expected.json         {"ok": true, ...}
  • ケース1つが、kata のプロジェクト1つに当たる。
  • 診断コード一覧の E01xx から E06xx の各コードに、少なくとも1つのケースを置く。
  • fix を返すコードには、その fix を適用した結果、その診断が消えることを確かめるテストも置く。
  • 診断が出ないことを確かめる ok- のケースも置く。

実行テスト

  • kata のソースをメモリ上でコンパイルし、生成したクラスをクラスローダーで読み込んで、メソッドを呼んで結果を確かめる。
  • 対象：算術と比較、if の分岐、while と for、リストと文字列の組み込みメソッド、範囲外アクセスのパニック、フィールドの読み書き、構築式、メソッド呼び出し、メソッド参照、リスト記法、0 による除算のパニック。
  • カウンターのサンプルでは、view が返す UI の値の中身と、increment を実行した後に view の結果が変わることを確かめる。
  • スタックトレースに kata のファイル名と行番号が出ることを確かめる。

端末での確認

scripts/e2e.sh が次を行う。接続中のエミュレータまたは実機が1台あることを前提にする。確認の本体は scripts/e2e.py（Python 3）で、画素の色は scripts/Pixel.java で読む。scripts/e2e.sh counter のように名前を渡すと、そのサンプルだけを確認する。

  1. kata build examples/counter を実行する。
  2. adb install -r で APK を入れ、アプリを起動する。
  3. uiautomator dump で画面の構造を取り出し、0 と表示されていることを確かめる。
  4. +1 のボタンの位置を取り出して adb shell input tap で押し、表示が 1 に変わることを確かめる。
  5. Reset を押し、表示が 0 に戻ることを確かめる。

このスクリプトは Gradle のテストには含めない。エミュレータが要るため、手元で明示的に実行する。

見た目の確認

examples/styled/ に、見た目の指定の全部品を使ったサンプルを置く。scripts/e2e.sh はこれもビルドして起動し、次を確かめる。

  • uiautomator dump の座標から、Width / Height で固定した大きさと Padding の余白が、dp を画素に換算した値と一致すること。
  • FillWidth を付けた部品の幅が、画面の利用できる幅と一致すること。
  • 画面を回転させた後も、操作で変えた表示が保たれていること（カウンターのサンプルで確かめる）。

色は、スクリーンショットの決めた位置の画素の値で確かめる。配置の部品（Center、AlignEnd、Expand など）も、同じサンプルの座標で確かめる。

入力欄とスクロールの確認

examples/form/ に、入力欄と、画面に収まらない長さの一覧を持つサンプルを置く。scripts/e2e.sh は次を確かめる。

  • 入力欄を押して adb shell input text で文字を送ると、その内容を使った別の Text の表示が変わること。端末の入力方式が文字を変換することがある（全角になるなど）ので、送った文字ではなく入力欄に表示された内容と比べる。
  • onChange が値を保存しなかった場合（サンプルでは4文字目以降）、入力欄が保存済みの内容に戻ること。
  • 続けてもう一度文字を送ると、入力欄を押し直さなくても続きに入力されること（再描画でフォーカスが保たれている）。
  • 一覧をスワイプすると、最初は画面外だった項目が表示されること。
  • スクロールした後にボタンを押して再描画しても、スクロールの位置が保たれていること。

電卓の確認

examples/calculator/ に四則演算の電卓を置く。scripts/e2e.sh はボタンを押して表示を確かめる：1.5 + 2.25 = 3.75、7 ÷ 2 = 3.5、0.1 + 0.2 = 0.3、6 × 7 = 42、5 ÷ 0 = Error、C で 0 に戻る。

入力部品の確認

examples/controls/ に入力部品と Divider、Loading、Tappable、Rounded を1つずつ置く。scripts/e2e.sh は、チェックボックスとスイッチの切り替え、つまみの移動、複数行の入力がそれぞれ隣の表示に反映されること、Slider・Progress・Divider が幅いっぱいであること、Tappable が押せること、Rounded の角が塗られていないことを確かめる。

選択と配置の部品の確認

examples/widgets/ に RadioGroup、Dropdown、Rating、Grid、Stack、Border、Card を置く。scripts/e2e.sh は、選択が隣の表示に反映されること、Dropdown が選ぶ前に onChange を実行しないこと、Grid の列が等幅で折り返すこと、Stack の子が重なること、Border の線が引かれることを確かめる。

画面の骨組みと重ねて出す部品の確認

examples/shell/ で、TopBar、Tabs、BottomNav、Fab、Chip、Badge、Label、BackBar、BackHandler（矢印と端末の「戻る」操作の両方）を確かめる。examples/overlays/ で、Alert の2つのボタン、BottomSheet と Modal の中のボタンと「戻る」操作での閉じ方、Snackbar のボタンと時間切れ、LazyList が見える行だけを作ること、スクロール後の行が押せることを確かめる。

画像、日付と時刻、メニューの確認

examples/media/ で、Image が画像の画素数どおりの dp で表示され画像の色が出ること、Icon が指定の大きさと色になること、Menu で選んだ番号が伝わること、DatePicker で別の日を押すと日付が変わること、TimePicker が渡した時刻を保ったまま表示し、時を選ぶと分を保って変わることを確かめる。

効果、操作、Web 表示の確認

examples/effects/ で、Opacity の色の混ざり方、Rotate で縦横が入れ替わること、Scale が周りに切り取られずに広がること、Gradient の上下の色、Theme の色が Fab に届くこと、Disabled の中のボタンが反応しないこと、Swipeable の左右、LongPress、SecretField が文字を隠したまま内容を伝えること、Animated の中で行が現れて消えること、WebView がページを表示し通信の権限が付いていることを確かめる。

保存、時刻、タイマー、通信の確認

examples/data/ で、Store の値がアプリを止めて起動し直しても残ること、Clock が妥当な年を返すこと、Timer が自分で数を増やし続けること、Request の失敗が onError に届くこと、通信の権限が付いていることを確かめる。通信の成功と各メソッドは、端末を使わないテスト（手元に立てたサーバーとの通信）で確かめる。

ToDo リストの確認

examples/todo/ は、3つのモジュール（データ、保存、画面）からなる ToDo リスト。scripts/e2e.sh は、追加（空の題名は追加されない）、完了の切り替え、3つの絞り込み、アプリを止めて起動し直した後も一覧が残ること、削除を確かめる。examples/data/ では、Device の画面の幅とクリップボードの往復も確かめる。

単位換算の確認

examples/converter/ で、長さ・重さ・温度の換算（14項目。不正な入力で = ? になることを含む）と、左右 16dp の余白、上部バーの高さ 64dp を確かめる。

実行方法

コマンド内容
./gradlew testエミュレータを使わないテストをすべて実行する。

scripts/e2e.sh端末での確認を実行する。
