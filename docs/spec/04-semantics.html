04 型と意味論

この章は M1 の型と検査規則を定める。括弧内の E.... は、規則に違反したときの診断コード。

型

型内容
Int64ビットの符号付き整数。あふれた場合は折り返す。
Float64ビットの浮動小数点数（IEEE 754 倍精度）。
Booltrue または false。
String不変の文字列。
Unit値を返さないメソッドの戻り値の型。戻り値の型以外には書けない（E0407）。
Action引数なしで Unit を返す処理。メソッド参照で作る。
Handler<T>T の値を1つ受け取って Unit を返す処理。メソッド参照で作る。T に Unit は書けない。
List<T>不変のリスト。リスト記法で作る。T に Unit は書けない。
クラス利用者定義のクラスと、組み込みの UI 部品。
インターフェースM1 では組み込みの Ui と Screen だけ。
  • Int、Float、Bool、String、Unit、Action、Handler、List は import なしで使える。それ以外の名前は import が要る（モジュールと import）。
  • null は存在しない。すべての変数とフィールドは常に値を持つ。
  • 型引数の数が合わない場合は E0408。

代入できる条件

型 S の値を型 T の場所に置けるのは、次のどちらかの場合だけ（それ以外は E0401）。

  1. S と T が同じ型である。
  2. T がインターフェースで、S がそれを implements しているクラスである。

暗黙の型変換はない。List<Text> を List<Ui> の場所に置くことはできない。

クラス

  • 継承はない。クラスは0個以上のインターフェースを実装できる。
  • 1つのクラスの中で、フィールドとメソッドの名前は重複できない（E0303）。オーバーロードはない。
  • インスタンスは参照で扱う。代入や引数渡しで複製されない。
  • implements したインターフェースのメソッドは、同じ名前、同じ引数、同じ戻り値の型ですべて定義する（E0506）。

フィールド

書き方値の決まり方
let name: String;構築式で必ず渡す。
var count: Int = 0;宣言に書いた式で決まる。構築式では渡せない。
  • 初期化の式の有無と let / var は独立に選べる。
  • 初期化の式の中で self は使えない（E0509）。
  • フィールドはどこからでも読める（obj.name）。

可変性

  • let のフィールドは書き換えられない（E0504）。
  • var のフィールドを書き換えられるのは、そのクラスのメソッドの中の self.x = 式; だけ。other.x = 式; は、同じクラスの別インスタンスであっても書けない（E0505）。
  • ローカル変数は、let なら書き換えられず、var なら書き換えられる。引数は書き換えられない（E0504）。

構築式

Button { label: "+1", onTap: self.increment }
Counter {}
  • 初期化の式を持たないフィールドを、宣言された順番で、すべて渡す。
  • 項目の不足、未知の項目、初期化の式を持つフィールドの指定、順番の違いは E0503。
  • 初期化の式は、フィールドの宣言順に評価される。
  • 構築できるのはクラスだけ。Int {} のようにクラスでない名前を書くと E0302。

メソッド

  • 最初の引数は必ず self。クラスに属さない関数と、self を取らない関数は M1 にない。
  • 戻り値の型は必ず書く。
  • 再帰呼び出しができる。

self

  • 自分のフィールドとメソッドには必ず self. を付けてアクセスする。
  • self. を付けずに書いた名前が、そのクラスのフィールドかメソッドの名前と一致する場合は E0304（修正案つき）。

名前とスコープ

  • ローカル変数は宣言した文の次から、そのブロックの終わりまで有効。
  • シャドーイングはできない。有効な引数やローカル変数と同じ名前で宣言すると E0303。並んだ別々のブロックで同じ名前を使うことはできる。
  • 未定義の名前は E0301、未定義の型は E0302。

メソッド呼び出しとメンバーアクセス

書き方意味
obj.name（name がフィールド）フィールドの値。
obj.name（name がメソッド）メソッド参照。
obj.name(引数)メソッド呼び出し。
  • 存在しないメンバーは E0501。フィールドに引数リストを付けた場合は E0508。
  • 引数は、self を除いた全部を、宣言された順番で、名前付きで渡す。不足、未知の名前、順番の違いは E0502（正しい引数リストを修正案として返す）。
  • 引数の式は、書かれた順番に評価される。

メソッド参照

obj.method は、その時点の obj に結び付いた処理の値を作る。型はメソッドの形で決まる。

メソッドの形メソッド参照の型
fn m(self) -> UnitAction
fn m(self, x: T) -> UnitHandler<T>
それ以外参照できない（E0507）
  • Action と Handler<T> の値は、UI 部品に渡すためのもの。kata のコードから呼び出す手段は M1 にない。
  • Handler<T> 同士は、T がちょうど同じ型のときだけ代入できる。

リスト記法

  • [a, b, c] は List<T> を作る。T は、その式が置かれた場所の型から決まる。
  • 各要素は T に代入できなければならない（E0401）。
  • 空のリストは [] と書く。
  • 置かれた場所の型が List<T> と決まらない位置には書けない（E0406）。メソッド呼び出しの対象（[a].m()）がこれに当たる。

kata ではすべての宣言に型を書くので、変数の初期化、代入、引数、構築式の項目、return のどれに置いても、型は周囲から一意に決まる。

演算子

演算子オペランド結果
+ - * / %Int と IntInt
+ - * / %Float と FloatFloat
単項 -Int または Floatオペランドと同じ型
< <= > >=Int と Int、または Float と FloatBool
== !=両辺が同じ型で、Int、Float、Bool、String のいずれかBool
&& ||Bool と BoolBool
!BoolBool
  • オペランドの型が合わない場合は E0402。
  • + で文字列は連結できない。concat を使う。
  • == は値の比較。クラスのインスタンスとリストは比較できない。
  • Int の / は 0 の方向に切り捨てる。% の符号は割られる数に従う。0 で割るとパニックになる。
  • Int と Float は混ぜられない（E0402）。toFloat() か toInt() で明示的にそろえる。
  • Float の演算は IEEE 754 に従う。0.0 で割ってもパニックにならず、結果は無限大か非数になる。非数は、自分自身を含むどの値とも == にならない。
  • && と || は左から評価し、結果が決まった時点で残りを評価しない。

組み込みメソッド

型メソッド内容
InttoString() -> String10進数の文字列にする。
InttoFloat() -> Float同じ値の Float にする。
FloattoString() -> String指数を使わない10進数の文字列にする。必ず小数点を含む（3.0、0.1）。読み戻すと元と同じ数になる桁数で出すので、0.1 + 0.2 は 0.30000000000000004 になる。無限大は Infinity / -Infinity、非数は NaN。
FloattoInt() -> Int小数部を切り捨てる（0 の方向）。Int の範囲を超える値は範囲の端になり、非数は 0 になる。
Floatround(decimals: Int) -> Float小数第 decimals 位までに丸める（ちょうど中間の値は 0 から遠い方へ）。decimals が負ならパニック。無限大と非数はそのまま返す。
StringtoFloat() -> Float10進数の文字列を数にする。受け付ける形は、先頭に任意の -、1桁以上の数字、任意で . と0桁以上の数字（12、-0.5、3.）。それ以外はパニック。
Stringconcat(other: String) -> String後ろに other をつないだ文字列を返す。
Stringlength() -> Int文字数（Unicode のコードポイントの数）。
List<T>size() -> Int要素の数。
List<T>get(index: Int) -> Tindex 番目（0始まり）の要素。範囲外ならパニックになる。
List<T>append(item: T) -> List<T>末尾に item を加えた新しいリストを返す。元のリストは変わらない。

リストは不変なので、フィールドのリストに要素を足すときは self.items = self.items.append(item: x); と書く。

文の規則

  • if と while の条件は Bool（E0403）。
  • 式だけの文に書けるのは、Unit を返すメソッド呼び出しだけ（E0206）。値を返す呼び出しの結果を捨てることはできない。
  • 代入の左辺に書けるのは、var のローカル変数か self.フィールド だけ（E0504、E0505）。

ループ

var total: Int = 0;
for (value: Int in self.history) {
  total = total + value;
}

var i: Int = 0;
while (i < 3) {
  i = i + 1;
}
  • while (条件) { ... } は、条件が true の間、ブロックを繰り返す。
  • for (名前: T in 式) { ... } は、List<T> の要素を先頭から順に取り出して繰り返す。式の型は、書いた T に対する List<T> とちょうど一致しなければならない（E0401）。
  • for の変数はブロックの中だけで有効で、書き換えられない（E0504）。名前の重複の規則は他のローカル変数と同じ（E0303）。
  • for の式は、最初に1回だけ評価される。
  • ループを途中で抜ける専用の文はない。メソッドごと抜ける return は使える。
  • 回数で繰り返すときは、var のカウンターと while を使う。

return

  • 戻り値の型が Unit 以外のメソッドは、すべての経路が return 式; で終わらなければならない（E0404）。
  • 戻り値の型が Unit のメソッドでは、return; で途中から抜けられる。末尾では書かなくてよい。値を付けることはできない（E0405）。
  • Unit 以外のメソッドで値のない return; は書けない（E0405）。
  • 経路が終わったと見なすのは、ブロックの最後の文が return である場合と、最後の文が else を持つ if で、すべての枝が終わっている場合。while と for は、中身にかかわらず経路を終わらせない。
  • return の後ろに文を書くことはできない（E0409）。

モジュールと import

  • 1ファイルが1モジュール。module 宣言の名前はファイルの位置と一致させる（E0601）。
  • kata で始まるモジュール名は、組み込みとランタイムのために予約されていて使えない（E0601）。
  • import は1行で1つの名前を取り込む。まとめて取り込む書き方はない。
  • M1 で import できるのは、組み込みモジュール kata.ui の名前だけ。それ以外は E0307。
  • import していない kata.ui の名前を使うと E0305（追加すべき import 文を修正案として返す）。
  • 使っていない import は E0306（削除を修正案として返す）。
  • M1 のプロジェクトは1モジュールで構成する。

パニック

  • M1 でパニックになるのは、Int の 0 による除算、数として読めない文字列の toFloat、負の桁数の round、List の get の範囲外アクセス、見た目の指定や入力部品の値が範囲外である場合。
  • パニックは捕まえられない。アプリは停止し、kata のファイル名と行番号を含むスタックトレースが logcat に出る。
