05 UI とアプリモデル

kata から使える UI は、組み込みモジュール kata.ui の名前だけで構成する。

kata.ui の宣言

kata.ui が提供する名前を kata の記法で示す。interface は M1 では利用者が書けないが、ここでは宣言の形を示すために使う。

  • UI 部品は値であり、作っただけでは画面に出ない。Screen の view が返したものが表示される。
  • Text と Button の見た目は Android の既定に従う。色や大きさを指定するときは見た目の指定の部品を、位置を指定するときは配置の部品を使う。
  • 利用者が実装できるインターフェースは Screen と Items だけで、Ui を実装するクラスは作れない（E0506）。画面の部品化は、Ui を返すメソッドで行う。

見た目の指定

見た目は、専用の部品で指定する。1つの部品は1つのことだけを指定し、重ねて使う。

Padding {
  all: 16,
  child: Background {
    color: Color { red: 255, green: 243, blue: 224, alpha: 255 },
    child: StyledText {
      text: self.count.toString(),
      size: 48,
      color: Color { red: 138, green: 59, blue: 18, alpha: 255 },
    },
  },
}
部品指定すること
Color色。red、green、blue、alpha はそれぞれ 0 から 255。alpha は 255 で不透明、0 で透明。Ui ではなく、他の部品の項目に渡す値。
StyledText文字の大きさ（size、単位は sp）と文字の色を指定した文字列。
StyledButton文字の色と背景の色を指定したボタン。
Paddingchild の四方に all（単位は dp）の余白を取る。
PaddingEdgeschild の左、上、右、下に、それぞれ指定した余白（単位は dp）を取る。
Backgroundchild の後ろを color で塗る。塗る範囲は child の大きさと同じ。
Roundedchild の後ろを、角を radius（単位は dp）で丸めた color で塗り、child もその形で切り抜く。
Borderchild の周りに、太さ width、角の丸み radius（どちらも単位は dp）の線を引く。child は線の内側に置かれる。
Cardchild の後ろに、角を丸めて影を付けた白い面を置く。
Width / Heightchild の幅または高さを dp（単位は dp）に固定する。
FillWidth / FillHeightchild の幅または高さを、親が与える範囲いっぱいに広げる。
  • 大きさを指定しない部品は、中身に合った大きさになる。
  • 色の値が 0 から 255 の範囲にない場合と、文字の大きさ、余白、dp、radius が負の場合は、描画するときにパニックになる。
  • 余白の内側を塗るときは Background の中に Padding を、外側だけ空けるときは Padding の中に Background を置く。
  • ルートの UI は、ステータスバーなどのシステムの表示と重ならない範囲の左上に置かれる。

配置

部品働き
ExpandColumn または Row の直接の子として置く。他の子を並べた残りの長さを、並べる方向に占める。Expand が複数あれば、中身の大きさにかかわらず等分し、child はその長さいっぱいに広がる。
Space縦横とも dp の大きさの空白。Column や Row の子の間に置いて間隔を空ける。
Center親が与える範囲いっぱいに広がり、child を縦横の中央に置く。
CenterHorizontal幅いっぱいに広がり、child を横の中央に置く。高さは child に合わせる。
CenterVertical高さいっぱいに広がり、child を縦の中央に置く。幅は child に合わせる。
AlignEnd幅いっぱいに広がり、child を右端に置く。高さは child に合わせる。
AlignBottom高さいっぱいに広がり、child を下端に置く。幅は child に合わせる。
  • 何も指定しない部品は、親の左上に置かれる。
  • Expand を Column と Row の直接の子以外に置いた場合は、child をそのまま表示する。
  • Scroll の中では高さに、HorizontalScroll の中では幅に上限がない。その方向に「いっぱいに広がる」部品は、child の大きさに合わせる。

大きさの決まり方

各部品の幅と高さは、「中身に合わせる」「親が与える範囲いっぱい」「固定（dp）」のいずれかになる。部品は、自分の大きさを決め、子に「どう広がるか」を渡す。表の「受け継ぐ」は、親から渡された値をそのまま使うことを表す。「引き継いで広げる」は、自分のその方向が「中身に合わせる」なら子も「中身に合わせる」、それ以外なら子は「いっぱい」になることを表す。

広がる指定は外側へ伝わる。「受け継ぐ」と書いた方向について、受け継いだ値が「中身に合わせる」であっても、自分の中にその方向へ広がる部品があれば、その部品は「いっぱい」になる。

  • 幅の方向へ広がる部品：FillWidth、Center、CenterHorizontal、AlignEnd、Slider、Progress、Divider、Grid、TopBar、BackBar、Tabs、BottomNav、LazyList、WebView、および Row の直接の子の Expand。
  • 高さの方向へ広がる部品：FillHeight、Center、CenterVertical、AlignBottom、および Column の直接の子の Expand。
  • この伝わり方は、Column、Row、Stack も通り抜ける。子の1つが横に広がる Column は、それ自体が横いっぱいになる。
  • 伝わりが止まる場所：大きさを固定する部品（幅なら Width、高さなら Height、両方なら Space）と、スクロールする方向（Scroll の高さ、HorizontalScroll の幅）。
  • ルートの部品は、幅も高さも「中身に合わせる」から始まる。
  • 例：Width { dp: 120, child: Height { dp: 48, child: Text { ... } } } の Text は 120dp × 48dp になる。
  • 例：Column の子はそのままでは中身の幅になる。横いっぱいにしたい子は FillWidth で包む。そうすると Column 自体も横いっぱいになる。
  • 例：画面の残りをスクロールする一覧に使うには、Column の子として Expand { child: Scroll { ... } } を置く。Column は高さいっぱいになり、一覧が残りを占める。

入力欄

class Greeter implements Screen {
  var name: String = "";

  fn view(self) -> Ui {
    return Column {
      children: [
        TextField { value: self.name, hint: "Name", onChange: self.setName },
        Text { text: "Hello, ".concat(other: self.name) },
      ],
    };
  }

  fn setName(self, value: String) -> Unit {
    self.name = value;
  }
}
  • 入力欄の内容は Screen のフィールドに持ち、value に渡す。入力欄そのものは内容を保持する場所ではない。
  • 利用者が内容を変えるたびに、変更後の文字列を引数にして onChange を実行する。その後は描画の流れに従って view を呼び直す。
  • 呼び直した view が返した value が、表示中の内容と同じなら何もしない。違う場合は表示を value に置き換え、カーソルを末尾に置く。この置き換えでは onChange を実行しない。
  • onChange の中で value に渡すフィールドを更新しないと、入力は次の再描画で元に戻る。
  • hint は、内容が空のときに薄く表示する文字列。不要なら "" を渡す。
  • 入力欄の幅は、既定では中身に合わせる。広げるときは FillWidth で包む。

画面の骨組み

部品内容
TopBar画面の上に置くタイトルのバー。幅いっぱいに広がる。
BackBar戻る矢印つきのタイトルのバー。矢印を押すと onBack を実行する。
Tabs等幅のタブの並び。selected は選ばれているタブの番号（0始まり）。別のタブを押すと、その番号で onChange を実行する。

  • 画面の切り替えは、状態に応じて view が返す UI を変えることで行う。専用の仕組みはない。
  • アプリには既定のタイトルバーがない。必要なら TopBar か BackBar を置く。
  • Tabs と BottomNav は、項目が1つ以上で、selected が 0 から項目数-1 でなければならない。Badge の count は 0 以上、Label の maxLines は 1 以上。違反は描画するときにパニックになる。

重ねて出す部品

Alert、Modal、BottomSheet、Snackbar は、view が返す UI の中に含まれている間だけ、画面の上に重ねて表示される。出すには UI に加え、消すには UI から外す。

fn view(self) -> Ui {
  var layers: List<Ui> = [self.page()];
  if (self.asking) {
    layers = layers.append(item: Alert {
      title: "Delete?",
      message: "This cannot be undone.",
      confirmLabel: "Delete",
      onConfirm: self.confirm,
      cancelLabel: "Keep",
      onCancel: self.cancel,
    });
  }
  return Stack { children: layers };
}
部品内容
Alert題名、本文、2つのボタンを持つダイアログ。ボタンを押すと onConfirm か onCancel を実行する。ダイアログの外を押すか「戻る」操作をした場合は onCancel。
Modalchild を画面の中央のダイアログに表示する。外を押すか「戻る」操作をすると onDismiss を実行する。
BottomSheetchild を画面の下から出る面に表示する。幅は画面いっぱい。閉じる操作は Modal と同じ。
Snackbar画面の下に短い知らせと1つのボタンを出す。ボタンを押すと onAction、押されないまま4秒たつと onDismiss を実行する。
  • これらは、書いた場所では大きさを持たない。どこに置いても周りの配置に影響しない。
  • 閉じるための処理（onCancel、onDismiss など）の中で、表示の条件にしているフィールドを戻す。戻さなければ、次の再描画でまた表示される。

長い一覧

class Inbox implements Screen, Items {
  fn view(self) -> Ui {
    return Column { children: [TopBar { title: "Inbox" }, Expand { child: LazyList { items: self } }] };
  }

  fn size(self) -> Int {
    return 1000;
  }

  fn item(self, index: Int) -> Ui {
    return Text { text: "Item ".concat(other: index.toString()) };
  }
}
  • LazyList は、画面に見えている行だけを作る縦の一覧。行数と各行の UI は、Items を実装したクラスが答える。
  • Items は Screen と同じく、利用者のクラスが実装できるインターフェース。画面のクラス自身が実装してもよい。
  • item は、行が画面に入るたびに、0 から size() - 1 の番号で呼ばれる。フィールドを書き換えてはならない。
  • LazyList は幅いっぱいに広がる。高さは自分では決まらないので、Expand や Height で与える。
  • 数十件までの一覧は Scroll と Column で足りる。件数が多いときに LazyList を使う。

画像とアイコン

  • 画像ファイルは、プロジェクトの assets/ ディレクトリに置く。中身はそのまま APK に入る。PNG、JPEG、WebP が使える。
  • Image { name: "photo.png" } は、assets/photo.png を表示する。name は assets/ からの相対パス。
  • 画像の1画素を 1dp として表示する。大きさを変えるときは Width や Height で包む。画像は縦横比を保ったまま、その範囲に収まるように縮小・拡大される。
  • Icon は、単色の画像を size（dp）の正方形に収め、color で塗って表示する。画像の不透明な部分の形だけが使われる。
  • name が文字列リテラルのとき、その名前のファイルが assets/ になければコンパイル時に E0605 になる。計算で作った名前は実行時に確かめられ、なければパニックになる。

日付、時刻、メニュー

  • Date と Time は値を表すクラスで、Ui ではない。month は 1 から 12、hour は 0 から 23。
  • DatePicker はカレンダー、TimePicker は24時間表記の時計を表示する。考え方は入力部品と同じで、選ばれた値は onChange に Date または Time として渡される。
  • 存在しない日付（2月30日など）や範囲外の時刻を value に渡すと、描画するときにパニックになる。
  • Menu は label を表示するボタンで、押すと options の一覧を開く。選ばれた項目の番号（0始まり）で onSelect を実行する。

効果、操作、Web 表示

部品内容
Theme画面全体の強調色を決める。入力部品、Tabs、BottomNav、Fab、Chip の色に使われる。UI の中に複数あるときは、最も外側で最初に書かれたものが画面全体に使われる。ないときは既定の青緑。
Opacitychild を半透明に描く。percent は 0（見えない）から 100（不透明）。
Rotatechild を、中心の周りに時計回りに degrees 度回して描く。
Scalechild を、中心を基準に percent％の大きさで描く（100 が等倍）。
Gradientchild の後ろを、上の from から下の to へ変わる色で塗る。
Disabledchild を薄く表示し、その中への操作をすべて無視する。
Swipeablechild の上で指を左右にはじくと、onSwipeLeft か onSwipeRight を実行する。child の中のボタンなどは、これまでどおり押せる。
LongPresschild を長押しすると onLongPress を実行する。
Animated中の変化（部品の出現と消滅、移動、大きさの変化）を、切り替えではなく動きで見せる。
SecretField入力した文字を隠す1行の入力欄。パスワード用。使い方は TextField と同じ。
NumberField数字用のキーボードを出す1行の入力欄。値は文字列のまま渡される。
WebViewurl の Web ページを表示する。幅いっぱいに広がり、高さは Expand などで与える。
  • Rotate と Scale は描き方だけを変える。部品が占める場所は変わらないので、周りの配置は動かない。
  • 部品は、自分の範囲の外に描かれた子（拡大や回転ではみ出した部分、影）を切り取らない。切り取るのは、スクロールする部品（Scroll、HorizontalScroll、LazyList）と Rounded、Card だけ。
  • Opacity の percent が 0 から 100 の範囲にない場合と、Scale の percent が負の場合は、描画するときにパニックになる。
  • WebView が表示できるのは、http://、https://、data: で始まる url と about:blank だけ。それ以外（file:、content:、javascript: など）は空のページになり、ページ内のリンクからも移動できない。ページからは端末のファイル、他のアプリのデータ、位置情報に届かない。外から受け取ったアドレスを渡しても、端末の中身を読まれないようにするため。
  • WebView を使うプログラムには、ビルド時に通信の権限（android.permission.INTERNET）が自動で付く。権限を手で宣言する場所はない。

画面の外とつながる

保存、時刻、タイマー、通信は、UI と同じ考え方で扱う。値を返すものは kata.sys のクラスのメソッドとして、時間のかかるものは「表示されている間だけ働く部品」として用意する。

保存（kata.sys.Store）

import kata.sys.Store;

class Counter implements Screen {
  var count: Int = Store {}.getInt(key: "count", fallback: 0);

  fn add(self) -> Unit {
    self.count = self.count + 1;
    Store {}.setInt(key: "count", value: self.count);
  }
}
メソッド内容
getString(key: String, fallback: String) -> String
getInt(key: String, fallback: Int) -> Int
getFloat(key: String, fallback: Float) -> Float
getBool(key: String, fallback: Bool) -> Bool		key に保存された値を返す。保存されていないか、その型として読めない場合は fallback を返す。
setString(key: String, value: String) -> Unit
setInt、setFloat、setBool も同じ形		key に値を保存する。アプリを終了しても残る。
remove(key: String) -> Unitkey の値を消す。
  • Store {} は何個作っても同じ保存場所を指す。保存場所はアプリごとに1つで、他のアプリからは読めない。
  • フィールドの初期化の式で読み、状態を変えるメソッドの中で書くのが基本の使い方。
  • 保存できるのは4種類の値だけ。リストやオブジェクトは、文字列に組み立てて保存する。

時刻（kata.sys.Clock）

メソッド内容
now() -> Int1970年1月1日 0時（UTC）からの経過ミリ秒。
today() -> Date端末のタイムゾーンでの今日の日付。
time() -> Time端末のタイムゾーンでの現在の時と分。

タイマー（Timer）

  • Timer { millis, onTick, child } は、表示されている間、millis ミリ秒ごとに onTick を実行して再描画する。止めるには UI から外す。
  • 見た目は child そのもの。millis は 1 以上（違反は描画するときにパニック）。

通信（Request）

fn view(self) -> Ui {
  if (self.loading) {
    return Request {
      method: "GET",
      url: "https://example.com/items",
      body: "",
      onResult: self.loaded,
      onError: self.failed,
      child: Loading {},
    };
  }
  return self.page();
}
  • Request は、表示されると HTTP の通信を1回行う。応答の本文（UTF-8 の文字列）を onResult に、失敗の説明を onError に渡し、再描画する。見た目は child そのもの。
  • 結果を受け取るメソッドの中で、表示の条件にしているフィールドを戻す。表示されたままでも、method、url、body が変わらない限り、通信をやり直さない。
  • 結果が届く前に UI から外すと、その結果は捨てられる。
  • method は GET、POST、PUT、DELETE。body が空でなければ本文として送る。指定したメソッドは、そのままサーバーに送られる。
  • 同じ通信（method、url、body の組）が送られるのは1回だけ。例外は GET で、結果を渡せなかった場合（結果が届いたときに部品が画面から外れていた場合）に限り、画面に戻ったときに取得し直す。POST などは、結果を渡せなくても送り直さない。注文や削除が二重に行われないようにするため。
  • 応答の状態が 200 番台でない場合は、HTTP 404 の形の説明で onError になる。
  • 応答の本文が 8MB を超える場合は、読むのをやめて onError になる。本文は1つの文字列としてメモリに載るので、相手のサーバーが送り続けてもアプリのメモリを使い切らないようにするため。接続と読み取りは、それぞれ15秒で打ち切る。
  • 使えるのは https:// のアドレス。http:// は Android が既定で拒否するため onError になる。
  • Request を使うプログラムには、通信の権限が自動で付く。
  • 応答の本文は文字列で渡される。JSON を読み取る機能は M1 にないので、String のメソッドで取り出す。

入力部品

Checkbox、Switch、Slider、TextArea、RadioGroup、Dropdown、Rating は、TextField と同じ考え方で動く。

  • 値（チェックの有無、オン・オフ、つまみの位置、文字列）は Screen のフィールドに持ち、部品に渡す。部品そのものは値を保持する場所ではない。
  • 利用者が操作すると、新しい値を引数にして onChange を実行し、view を呼び直す。
  • onChange の中で値を保存しないと、次の再描画で表示が元に戻る。この戻しでは onChange を実行しない。
  • Slider の onChange は、つまみを動かしている間、値が変わるたびに実行される。
  • Slider と Progress は、max が 1 以上で、value が 0 から max の範囲でなければならない。Rating も同じ。TextArea の lines は 1 以上。RadioGroup の selected は -1 から項目数-1、Dropdown は項目が1つ以上で selected が 0 から項目数-1。Grid の columns は 1 以上。違反は描画するときにパニックになる。
  • RadioGroup、Dropdown、Rating の onChange は、利用者が今の値と違うものを選んだときだけ実行される。

Screen

  • 画面は Screen を実装したクラスで表す。状態はそのクラスの var フィールドに持つ。
  • view は、現在のフィールドの値から表示すべき UI を組み立てて返す。
  • view の中でフィールドを書き換えてはならない。M1 ではコンパイラはこれを検査しない。

描画の流れ

  1. 起動時に、app 宣言の root の式を1回評価して、ルートの Screen を作る。
  2. ルートの view を呼び、返った UI を画面に表示する。
  3. ボタンが押されると onTap を、入力欄の内容が変わると onChange を実行する。
  4. 実行が終わったら、ルートの view を呼び直し、返った UI を前回の UI と比べて、変わった部分だけを画面に反映する。
  • すべてメインスレッドで順番に実行する。
  • 画面の回転では Activity を作り直さないので、状態は保たれる（マニフェストの設定による）。OS がアプリのプロセスを終了させた場合は、次の起動で初期値に戻る。
  • 処理が終わるまで画面は更新されない。終わらないループを書くとアプリは応答しなくなる。

変わった部分だけの反映

新しい UI と前回の UI を、ルートから同じ位置同士で比べる。

  • 同じ位置にある部品の種類が同じなら、画面上の実体をそのまま使い、値が変わった項目だけを更新する。子も同じ規則で比べる。
  • 種類が違うなら、その位置から下を捨てて作り直す。
  • Column と Row の子は、先頭から順番に同じ位置として比べる。新しいほうが多ければ末尾に足し、少なければ末尾を取り除く。

この規則により、種類が変わらない位置にある入力欄のフォーカスとカーソル、スクロールの位置は、再描画をまたいで保たれる。

app 宣言

app {
  id: "dev.kata.counter",
  name: "Counter",
  root: Counter {},
}
項目型内容
id文字列リテラルアプリの ID。[a-z][a-z0-9]* をピリオドで2つ以上つないだ形。
name文字列リテラルランチャーに表示する名前。空にはできない。

  • app 宣言はプロジェクト全体でちょうど1つ（E0602）。
